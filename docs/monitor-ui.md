# Monitor UI

## Назначение панели

`modules/analytic-monitor` — это пользовательская панель наблюдения за аналитическим контуром. Она не генерирует данные сама, а показывает, что backend действительно отдает метрики по REST или WebSocket.

## Структура интерфейса

На экране `MonitorPanel` отображаются следующие блоки:

| Блок | Что делает |
| --- | --- |
| Поле `API Key` | ввод ключа доступа для REST и WebSocket |
| Поле `UUID товара` | ввод `manufactureId`, для которого нужно читать аналитику |
| Переключатель режима | выбор между `REST polling` и `WebSocket` |
| Поле `Интервал опроса (мс)` | задает периодичность запросов в режиме REST |
| Кнопки `Start / Restart` и `Stop` | запуск, перезапуск и остановка активного соединения |
| Блок статуса | показывает текущее состояние соединения |
| Блок `Результаты` | выводит текущий JSON-ответ или сообщение об ошибке |
| Блок `График динамики` | строит историю трех метрик во времени |

## Режимы работы

### REST polling

- запрос идет на `http://localhost:8001/api/{manufactureId}/show`
- заголовок: `X-API-KEY`
- после `Start` монитор делает первый запрос сразу, затем повторяет его через `setInterval`
- период задается пользователем, по умолчанию `2000` мс

### WebSocket

- подключение идет на `ws://localhost:8001/ws/analytics`
- `manufactureId` и `apiKey` передаются в query string
- после подключения монитор ждет только новые сообщения
- UI явно предупреждает: `WebSocket получает только новые обновления после подключения`

## Какие данные показывает монитор

### Текущий снапшот

В блоке `Результаты` показывается текущий объект аналитики:

- `averageRank`
- `globalCount`
- `referCount`

### История

Монитор хранит до `60` последних точек (`MAX_POINTS = 60`).

Для каждой точки сохраняются:

- время получения или `generatedAt` из WebSocket-сообщения;
- числовое значение `averageRank`;
- числовое значение `globalCount`;
- числовое значение `referCount`.

## Как строится график

- библиотека: `Chart.js` через `react-chartjs-2`
- тип графика: `Line`
- ось `X`: `timestamp.toLocaleTimeString()`
- ось `Y`: начинается с нуля
- серии:
  - `averageRank` — зеленая
  - `globalCount` — синяя
  - `referCount` — красная

График показывает динамику уже полученных ответов клиента, а не прямой поток из Kafka.

## Какие ошибки интерфейс умеет показывать

### REST

- `403`: неверный API key
- `500`: внутренняя ошибка backend
- другой HTTP status: отображается код и `statusText`
- отсутствие ответа: сообщение о недоступности сервера
- общая ошибка запроса: `err.message`

### WebSocket

- ошибка соединения
- некорректный JSON в сообщении
- разрыв соединения с кодом `1006`
- закрытие сокета с любым нестандартным кодом

## Как монитор используется для контроля аналитического модуля

Практический сценарий контроля выглядит так:

1. получить актуальный `manufactureId` через `GET /simulator/config`;
2. вставить его в панель;
3. выбрать `REST polling` для периодического чтения агрегатов;
4. переключиться на `WebSocket`, чтобы убедиться, что push-обновления приходят после новых Kafka-событий;
5. смотреть на рост JSON-полей и графика.

Именно поэтому монитор является финальным пользовательским индикатором работоспособности всего контура, а не только frontend-компонентом.

## Ограничения

- Backend URL и WebSocket URL захардкожены: `http://localhost:8001/api` и производный `ws://localhost:8001/ws/analytics`.
- Панель не умеет получать список `manufactureId`; UUID нужно вводить вручную.
- В режиме WebSocket при подключении не загружается стартовое состояние, поэтому без новых событий экран может оставаться пустым.
